# Design

## Scope

`media-projector` is a filesystem compatibility layer, not a media manager. It
does not fetch metadata, inspect stream contents, call Jellyfin, mutate torrent
data, or persist an index. The desired projection is a pure function of the
currently stable source files.

Preflight mode runs the same scanner and matcher but serializes their inputs,
derived identities, decisions, and failures as versioned JSON. It never enters
target preparation or reconciliation, which makes target mutation impossible
by construction in that mode.

## Lifecycle

```text
startup
  → validate source, target ownership, overlap, and filesystem
  → full reconcile
  → install recursive native watcher
  → wait for quiet event window
  → full reconcile

every scan interval
  → full reconcile even when no event was observed
```

Linux `inotify` events provide low-latency and low-idle-cost updates. Access
events generated by the scanner itself are discarded before debouncing, so a
reconciliation cannot trigger another reconciliation. The periodic scan
repairs state after missed events, unsupported network mounts, container
restarts, or changes made while the process was stopped. No correctness claim
depends solely on event delivery.

## Source entries and flattening

The default flat layout treats the complete recursive source tree as one entry
and projects every video and matched sidecar into the target root. This is
suited to a source containing movies.

The `--group-by-directory` layout treats every direct child directory as an
independent entry. Its video, audio, and subtitle files are scanned recursively,
then projected into one target directory with the same top-level name. This is
suited to a source whose direct children are shows. Recognized files directly in
the source are treated as a shared root entry.

The entry boundary also scopes sidecar matching. A subtitle below one show can
never be matched to a video below another show in grouped mode.

Duplicate video basenames are deterministic: the relative parent path is added
as a suffix, followed by a stable path hash only if that is still not unique.

## Sidecar matching

Matching never uses remote metadata. Within one source entry it tries, in order:

1. A unique normalized basename match after removing bracketed release tags and
   punctuation.
2. A unique episode identity match. Supported forms include `S01E02`, `1x02`,
   `Episode 02`, `Ep 02`, `02v2`, and a conservative trailing episode number.
   `Season 2/02.ass` carries both season and episode context from its path.
3. The only video in the entry, which safely covers a movie or single-episode
   release.

Zero candidates and multiple candidates are both skipped. The warning contains
the source path and reason, so adding a later explicit mapping mechanism remains
possible without weakening the default matcher.

The output sidecar suffix is derived from meaningful parent directories and
filename tokens not shared with the video. Generic names such as `Subs` and
`Audio` are omitted, while `ru`, `signs`, `forced`, or a release-group name are
retained. Common language names and two- or three-letter aliases are normalized
to Jellyfin-compatible language tags, while descriptive directory labels remain
available as track titles. A deterministic hash resolves any remaining filename
collision.

## Stability boundary

A recognized file is eligible only when its modification time is at least
`--settle` seconds old. This avoids projecting the most common active-download
state without keeping a database. It is deliberately a heuristic, not a torrent
completion protocol. Moving completed torrents into the source is stronger.

## Reconciliation and failure behavior

The plan maps each relative target path to one source path. Reconciliation:

1. Keeps a target file when its device and inode already match the source.
2. Creates a hardlink under a temporary name and atomically renames it into
   place for additions and replacements.
3. Removes projection files absent from the plan.
4. Removes empty projection directories.

The target ownership marker, path-component validation, non-overlap check, and
same-filesystem check happen before reconciliation. The scanner does not follow
source symlinks, and cleanup does not follow target symlinks.

An initial configuration or filesystem error exits the process. A later
transient reconciliation error is logged at `error` and the daemon continues so
the next event or periodic scan can repair the projection.
